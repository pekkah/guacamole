# Quickstart: Query API PoC Validation

## Overview
This quickstart demonstrates the Query API PoC through snapshot tests that validate source generator output and verify alignment with incremental computation principles.

## Prerequisites
- .NET 10 RC1 SDK
- Existing Guacamole solution structure
- XUnit v3 testing framework
- Verify.SourceGenerators package

## Step 1: Define a Simple Query

Create a test query class to validate the API design:

```csharp
// Example query for testing
public class CalculateLengthQuery : IQuery<string, int>
{
    public async Task<Result<int>> ExecuteAsync(
        QueryContext context,
        string input,
        CancellationToken cancellationToken = default)
    {
        await Task.Delay(1, cancellationToken); // Simulate async work
        return Result.Success(input?.Length ?? 0);
    }
}
```

**Expected Behavior**:
- Framework generates registration code automatically
- QueryContext provides strongly-typed access
- Result<T> handles success/failure states
- Dependency injection resolves constructor dependencies

## Step 2: Define a Dependent Query

Create a query that depends on another query:

```csharp
public class ValidateInputQuery : IQuery<string, bool>
{
    public async Task<Result<bool>> ExecuteAsync(
        QueryContext context,
        string input,
        CancellationToken cancellationToken = default)
    {
        // Access another query through context
        var lengthResult = await context.CalculateLength()
            .ExecuteAsync(context, input, cancellationToken);

        if (!lengthResult.IsSuccess)
            return Result.Failure<bool>(lengthResult.Error);

        return Result.Success(lengthResult.Value > 0 && lengthResult.Value < 100);
    }
}
```

**Expected Behavior**:
- Strongly-typed access via `context.CalculateLength()`
- Automatic dependency tracking
- Error propagation through Result<T> chain
- Incremental invalidation when dependencies change

## Step 4: Test Circular Dependency Detection

Verify compile-time and runtime guards:

```csharp
[Fact]
public Task DetectsCircularDependencies()
{
    var source = @"
public class QueryA : IQuery<string, int>
{
    public async Task<Result<int>> ExecuteAsync(QueryContext context, string input, CancellationToken cancellationToken = default)
    {
        var result = await context.QueryB().ExecuteAsync(context, input, cancellationToken);
        return Result.Success(result.Value + 1);
    }
}

public class QueryB : IQuery<string, int>
{
    public async Task<Result<int>> ExecuteAsync(QueryContext context, string input, CancellationToken cancellationToken = default)
    {
        var result = await context.QueryA().ExecuteAsync(context, input, cancellationToken);
        return Result.Success(result.Value + 1);
    }
}";

    return TestHelper.VerifyDiagnostics(source);
}
```

**Expected Behavior**:
- Compile-time warning about circular dependency
- Runtime exception if circular execution attempted
- Clear error messages with suggested fixes

## Step 5: Validate Performance Characteristics

Test incremental computation behavior:

```csharp
[Fact]
public async Task ValidatesIncrementalBehavior()
{
    // Arrange
    var context = CreateTestContext();
    var query = new TestQuery();

    // Act - First execution
    var result1 = await query.ExecuteAsync(context, "test", CancellationToken.None);
    var executionTime1 = result1.ExecutionTime;

    // Act - Second execution (should be cached)
    var result2 = await query.ExecuteAsync(context, "test", CancellationToken.None);
    var executionTime2 = result2.ExecutionTime;

    // Assert
    Assert.True(result1.IsSuccess);
    Assert.True(result2.IsSuccess);
    Assert.True(result2.WasCached);
    Assert.True(executionTime2 < executionTime1); // Cached should be faster
}
```

**Expected Behavior**:
- First execution performs computation
- Second execution returns cached result
- Cache invalidation triggers recomputation
- O(changes) complexity for updates
