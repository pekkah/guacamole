## What is Guacamole?

Guacamole is a .NET framework for building **incremental computation pipelines**. Inspired by Roslyn's incremental generators, it automatically tracks dependencies between computations and only recomputes what's necessary when inputs change.

**Perfect for:**
- Incremental compilers
- Build systems
- Data transformation pipelines
- File processing systems
- Any scenario where you want to avoid redundant computation

**Key Benefits:**
- ⚡ **Automatic caching** - Computed values are cached until their inputs change
- 🔄 **Smart invalidation** - Only affected computations are rerun
- 🧵 **Thread-safe** - Built-in locking for concurrent access
- 🎯 **Type-safe** - Strongly-typed APIs generated at compile-time
- 🔌 **DI-ready** - First-class dependency injection support

## Core Concepts

Guacamole is built around three fundamental concepts:

### 1. Computing Context

A **Computing Context** is a class that orchestrates your incremental computations. It:
- Inherits from `ComputingContextBase`
- Is marked with `[ComputingContext]` attribute
- Defines properties for inputs and computed values
- Automatically gets mutation methods generated by source generators

### 2. Providers

**Providers** are immutable pipeline structures that represent values or collections:

- **`IncrementalValueProvider<T>`** - Represents a single value
- **`IncrementalValuesProvider<T>`** - Represents a collection of values

Providers are **lazy** - they only compute when accessed and cache their results.

### 3. Computation Graph

The **Computation Graph** automatically tracks dependencies between providers. When you update an input, the graph knows exactly which downstream computations need to be invalidated.

## Your First Computing Context

Let's build a simple compiler context that parses source code incrementally.

### Step 1: Define Your Context

```csharp
using System;
using Guacamole;
using Guacamole.Core.Providers;

namespace MyCompiler;

[ComputingContext]
public partial class CompilerContext : ComputingContextBase
{
    // Get-only properties are AUTO-MANAGED by the framework
    // The source generator will create mutation methods for these
    public partial IncrementalValueProvider<string> SourceCode { get; }

}
```

**What happens here?**
- `[ComputingContext]` tells the source generator to process this class
- `partial` keyword allows the generator to add code
- `IncrementalValueProvider<string> SourceCode { get; }` - get-only property means "framework, manage this for me"
- Computation nodes are automatically initialized lazily on first property access - no manual initialization needed!

### Step 2: Generated Code (Automatic!)

The source generator automatically creates:

```csharp
// ✨ Auto-generated mutation method
public void SetSourceCode(string value)
{
    // Thread-safe change tracking
    // Deferred cache invalidation
}

// ✨ Auto-generated SaveChanges
public void SaveChanges()
{
    // Applies all pending changes
    // Invalidates affected caches
    // Triggers output handlers
}

// ✨ Auto-generated property
public bool HasPendingChanges { get; }
```

### Step 3: Use Your Context

```csharp
using Microsoft.Extensions.DependencyInjection;

// Setup dependency injection
var services = new ServiceCollection();
services.AddComputingContext<CompilerContext>();
var provider = services.BuildServiceProvider();

// Get your context
using var context = provider.GetComputingContext<CompilerContext>();

// Update input
context.SetSourceCode("let x = 42");

// Commit changes (triggers computation)
context.SaveChanges();

// Access the value
var result = context.SourceCode.GetValue();
if (result.IsSuccess)
{
    Console.WriteLine($"Source: {result.Value}");
}
```

## Working with Providers

### Single Value Providers (`IncrementalValueProvider<T>`)

Use for properties that hold a single value:

```csharp
[ComputingContext]
public partial class MyContext : ComputingContextBase
{
    public partial IncrementalValueProvider<Project> Project { get; }
    public partial IncrementalValueProvider<string> Output { get; }

}

// Usage
context.SetProject(new Project { Name = "MyApp" });
context.SetOutput("Built successfully");
context.SaveChanges();
```

**Auto-generated methods:**
- `SetProject(Project value)` - Sets the project
- `SetOutput(string value)` - Sets the output

### Collection Providers (`IncrementalValuesProvider<T>`)

Use for properties that hold collections:

```csharp
[ComputingContext]
public partial class BuildContext : ComputingContextBase
{
    public partial IncrementalValuesProvider<SourceFile> SourceFiles { get; }

}

// Usage
context.AddSourceFiles(new SourceFile("Program.cs", "// code"));
context.AddSourceFiles(new SourceFile("Utils.cs", "// utils"));
context.SaveChanges();
```

**Auto-generated methods:**
- `AddSourceFiles(SourceFile item)` - Add single item (throws on duplicate)
- `RemoveSourceFiles(SourceFile item)` - Remove item (returns false if not found)
- `ReplaceSourceFiles(SourceFile oldItem, SourceFile newItem)` - Replace item
- `AddSourceFiless(IEnumerable<SourceFile> items)` - Batch add
- `RemoveSourceFiless(IEnumerable<SourceFile> items)` - Batch remove

### Transformation Pipelines

Transform providers using LINQ-style methods:

```csharp
[ComputingContext]
public partial class ParserContext : ComputingContextBase
{
    // Auto-managed input
    public partial IncrementalValuesProvider<SourceFile> SourceFiles { get; }

    // User-managed derived value (has setter = you manage it)
    public partial IncrementalValuesProvider<SyntaxTree> ParsedFiles { get; set; }

    public ParserContext()
    {
        // Create transformation pipeline
        ParsedFiles = SourceFiles
            .Select(file => Parse(file))
            .Where(tree => tree.HasErrors == false);
    }

    private SyntaxTree Parse(SourceFile file)
    {
        // Your parsing logic
        return new SyntaxTree(file);
    }
}
```

**Available transformations:**
- `Select(Func<T, TResult>)` - Transform each item
- `Where(Func<T, bool>)` - Filter items
- `SelectMany(Func<T, IEnumerable<TResult>>)` - Flatten collections
- `Combine(otherProvider)` - Combine two providers

## Making Updates

### The Two-Phase Update Model

Guacamole uses a **two-phase commit model** similar to Entity Framework:

1. **Mutation Phase** - Make changes (tracked but not applied)
2. **Commit Phase** - Call `SaveChanges()` to apply and trigger recomputation

```csharp
// Phase 1: Track changes
context.SetProject(new Project { Name = "MyApp" });
context.AddSourceFiles(new SourceFile("Main.cs", "..."));
context.AddSourceFiles(new SourceFile("Helper.cs", "..."));

Console.WriteLine(context.HasPendingChanges); // true

// Phase 2: Commit and recompute
context.SaveChanges();

Console.WriteLine(context.HasPendingChanges); // false
```

**Why two phases?**
- **Batch updates** - Make multiple changes efficiently
- **Atomic operations** - All changes apply together or not at all
- **Predictable recomputation** - You control when computation happens

### Discarding Changes

Changed your mind? Discard pending changes:

```csharp
context.AddSourceFiles(someFile);
context.SetProject(someProject);

// Oops, changed my mind
context.DiscardChanges();

Console.WriteLine(context.HasPendingChanges); // false
```

### Async Support

For async workflows:

```csharp
context.SetSourceCode(newCode);
await context.SaveChangesAsync(cancellationToken);
```

## Understanding Caching

Guacamole's caching is the secret sauce that makes incremental computation efficient.

### How Caching Works

1. **First Computation** - When you access a provider's value, it computes and caches the result
2. **Cache Hits** - Subsequent accesses return the cached value (no recomputation)
3. **Invalidation** - When inputs change, affected caches are invalidated
4. **Recomputation** - Next access recomputes only invalidated values

### Example: Incremental Parsing

```csharp
[ComputingContext]
public partial class IncrementalParser : ComputingContextBase
{
    public partial IncrementalValuesProvider<SourceFile> Files { get; }
    public partial IncrementalValuesProvider<SyntaxTree> Trees { get; set; }

    public IncrementalParser()
    {
        Trees = Files.Select(file => Parse(file)); // Cached per file
    }


    private SyntaxTree Parse(SourceFile file)
    {
        Console.WriteLine($"Parsing {file.Path}...");
        return new SyntaxTree(file);
    }
}

// Usage
context.AddFiles(new SourceFile("A.cs", "..."));
context.AddFiles(new SourceFile("B.cs", "..."));
context.SaveChanges();

var trees1 = context.Trees.GetValue(); // Parses A.cs and B.cs

// Only A.cs changed
context.ReplaceFiles(
    new SourceFile("A.cs", "..."),
    new SourceFile("A.cs", "... updated")
);
context.SaveChanges();

var trees2 = context.Trees.GetValue(); // Only re-parses A.cs!
// B.cs result comes from cache ✨
```

### Equality-Based Caching

Caching uses **equality comparison** to detect actual changes:

```csharp
context.SetProject(new Project("MyApp")); // Set initial value
context.SaveChanges(); // Computation happens

// Set to same value
context.SetProject(new Project("MyApp")); // Records change
context.SaveChanges(); // NO recomputation! (equal to cached value)
```

**Requirements:**
- Types must properly implement `Equals()` and `GetHashCode()`
- Records work great (built-in value equality)

### Cache Invalidation Strategy

When you update an input, Guacamole invalidates:
1. The input node's cache
2. All nodes that **transitively depend** on that input

```
SourceFiles → ParsedTrees → Diagnostics → Report
     ↓             ↓              ↓          ↓
  [UPDATE]     [INVALID]     [INVALID]  [INVALID]
```

This ensures correctness while minimizing recomputation.

## Advanced Topics

### Output Handlers

Register handlers to be notified when computations complete:

```csharp
[ComputingContext]
public partial class WatchedContext : ComputingContextBase
{
    public partial IncrementalValuesProvider<SourceFile> Files { get; }

    public WatchedContext()
    {
        // Register output handler
        RegisterOutput(Files, (files, ctx) =>
        {
            Console.WriteLine($"Files changed! Count: {files.Count()}");
            foreach (var file in files)
            {
                Console.WriteLine($"  - {file.Path}");
            }
        });
    }

}

// Output handler is called after SaveChanges()
context.AddFiles(new SourceFile("Test.cs", "..."));
context.SaveChanges(); // Handler executes here
// Output: Files changed! Count: 1
//         - Test.cs
```

**Handler behavior:**
- Called after successful `SaveChanges()`
- Only called if the provider's value changed
- Receives computed value and context

### Custom Comparers

Override default equality for fine-grained cache control:

```csharp
[ComputingContext]
public partial class SmartCache : ComputingContextBase
{
    public partial IncrementalValuesProvider<Document> Documents { get; }

    public SmartCache()
    {
        // Use custom comparer (e.g., by ID only)
        Documents.WithComparer(new DocumentIdComparer());
    }

}

class DocumentIdComparer : IEqualityComparer<Document>
{
    public bool Equals(Document? x, Document? y) => x?.Id == y?.Id;
    public int GetHashCode(Document obj) => obj.Id.GetHashCode();
}
```

### User-Managed vs Auto-Managed Properties

**Auto-managed** (get-only) - Framework generates everything:
```csharp
public partial IncrementalValueProvider<string> Input { get; }
// ✨ SetInput() method generated
// ✨ Change tracking generated
// ✨ Cache invalidation generated
```

**User-managed** (has setter) - You're in control:
```csharp
public partial IncrementalValueProvider<string> Computed { get; set; }
// ❌ No mutation methods generated
// ✅ You set it manually in constructor
// ✅ You manage its lifetime
```

```csharp
public MyContext()
{
    // You wire up user-managed properties
    Computed = Input.Select(x => x.ToUpper());
}
```

### Example 3: Incremental Compiler

```csharp
[ComputingContext]
public partial class CompilerContext : ComputingContextBase
{
    public partial IncrementalValueProvider<Project> Project { get; }
    public partial IncrementalValuesProvider<SourceFile> SourceFiles { get; }
    public partial IncrementalValuesProvider<SyntaxTree> SyntaxTrees { get; set; }
    public partial IncrementalValuesProvider<Diagnostic> Diagnostics { get; set; }

    public CompilerContext()
    {
        // Parse files (incremental - cached per file)
        SyntaxTrees = SourceFiles.Select(file => Parse(file));

        // Gather diagnostics (only recomputed for changed files)
        Diagnostics = SyntaxTrees.SelectMany(tree => tree.Diagnostics);

        // Output handler for errors
        RegisterOutput(Diagnostics, (diagnostics, ctx) =>
        {
            foreach (var diag in diagnostics.Where(d => d.Severity == Severity.Error))
            {
                Console.WriteLine($"Error: {diag.Message}");
            }
        });
    }


    private SyntaxTree Parse(SourceFile file)
    {
        Console.WriteLine($"Parsing {file.Path}...");
        return Parser.Parse(file.Content);
    }
}

// Initial compilation
context.SetProject(new Project("MyApp", "1.0"));
context.AddSourceFiles(new SourceFile("Program.cs", programCode));
context.AddSourceFiles(new SourceFile("Helper.cs", helperCode));
context.SaveChanges();
// Output: Parsing Program.cs...
//         Parsing Helper.cs...

// Edit one file
var oldProgram = new SourceFile("Program.cs", programCode);
var newProgram = new SourceFile("Program.cs", updatedProgramCode);
context.ReplaceSourceFiles(oldProgram, newProgram);
context.SaveChanges();
// Output: Parsing Program.cs...
// (Helper.cs not re-parsed - from cache!)
```

## Troubleshooting

### Common Issues

**Q: My changes aren't taking effect**
```csharp
// ❌ Forgot to call SaveChanges()
context.SetInput(value);
var result = context.Output.GetValue(); // Old value!

// ✅ Always call SaveChanges()
context.SetInput(value);
context.SaveChanges();
var result = context.Output.GetValue(); // New value!
```

**Q: Everything recomputes even though only one input changed**
```csharp
// ❌ Types without proper equality
public class MyType
{
    public string Value { get; set; }
    // Missing Equals/GetHashCode - reference equality used!
}

// ✅ Use records for value equality
public record MyType(string Value);
```

**Q: Duplicate item errors**
```csharp
// ❌ Adding duplicates
context.AddItems("A");
context.AddItems("A"); // Throws ContextOperationException!

// ✅ Check before adding or use Replace
var itemsResult = context.Items.GetValue();
if (itemsResult.IsSuccess && !itemsResult.Value.Contains("A"))
{
    context.AddItems("A");
}
```

## Summary

Guacamole makes incremental computation simple:

1. **Define** a computing context with `[ComputingContext]`
2. **Declare** get-only properties for auto-managed inputs
3. **Transform** using LINQ-style provider methods
4. **Update** via generated mutation methods
5. **Commit** with `SaveChanges()` to trigger recomputation
6. **Benefit** from automatic caching and smart invalidation

Happy incremental computing! 🥑
